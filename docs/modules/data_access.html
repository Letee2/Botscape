Capa de Acceso a Datos (Python)

La interacción entre la aplicación y PostgreSQL se gestiona mediante una arquitectura modular ubicada en botscape/shared/db/. Este diseño desacopla la gestión de conexiones, la ingesta masiva y las consultas analíticas.

1. Gestión de Conexiones (core.py)

Módulo de bajo nivel encargado del ciclo de vida de las conexiones utilizando el driver psycopg (v3).

  • Configuración Centralizada: Carga credenciales y DSN desde botscape.config.settings.
  • Row Factory: Configura las conexiones con psycopg.rows.dict_row, permitiendo acceder a los resultados como diccionarios (ej. row['token']) en lugar de tuplas numéricas.
  • Transaccionalidad:
    • execute_sql(sql, params): Ejecuta escrituras atómicas con commit y rollback automáticos.
    • get_conn(): Provee conexiones crudas para procesos que requieren gestión manual de transacciones (ej. operaciones en lote).

2. Ingesta de Datos (ingest.py)

Optimizado para el servicio Listener, este módulo maneja la escritura intensiva de datos en tiempo real.

Tipado Estricto

Se emplean dataclasses para validar la estructura de los datos antes de la persistencia:

  • MessageRecord: Normalización de mensajes de Telegram.
  • EntityRecord: IOCs extraídos (URLs, emails, wallets).
  • AttachmentRecord: Metadatos de archivos adjuntos.

Mecanismos de Idempotencia

Implementa lógica Upsert para garantizar la integridad de los datos sin interrumpir el flujo:

  • Mensajes (insert_message): Usa ON CONFLICT DO NOTHING. Siempre retorna el ID del mensaje (nuevo o existente) para mantener la integridad referencial.
  • Entidades (insert_entities_batch): Utiliza executemany para inserciones en bloque, actualizando la métrica de confianza (confidence) si la entidad ya existe.

3. Lógica de Dominio (actions.py)

Encapsula operaciones transaccionales complejas de la lógica de negocio, utilizadas por el Profiler y la administración.

  • Control de Bots: Funciones para activar o pausar la monitorización (set_bot_status).
  • Perfilado IA (save_bot_profile): Persiste el análisis generado por el LLM y gestiona el etiquetado semántico. Utiliza una estrategia de Clean Slate con CTEs (Common Table Expressions) para gestionar etiquetas de forma atómica (creación y asignación en un solo paso).

4. Consultas Especializadas (queries/)

Para mantener el código limpio y mantenible, las consultas SQL de lectura se han separado del código de aplicación y organizado por dominio funcional en el paquete botscape/shared/db/queries/.

Esto permite reutilizar lógica compleja entre el Dashboard y los scripts de análisis.

  • profiling.py: Recuperación de datos contextuales para el análisis de IA.
  • graph.py: Extracción de nodos y aristas optimizada para la visualización de redes (NetworkX/Agraph).
  • overview.py: Cálculo de KPIs globales y series temporales para el cuadro de mando.
  • breach.py: Consultas específicas para el módulo de monitorización defensiva.

5. Caché para Dashboard (caching.py)

Capa de abstracción diseñada para Streamlit, enfocada en el rendimiento de lectura.

  • Integración con Pandas: Transforma los resultados de psycopg directamente en pd.DataFrame, gestionando los tipos de datos automáticamente.
  • Estrategia de Caché: Implementa decoradores @st.cache_data con TTLs ajustados al caso de uso:
    • Datos analíticos (read_sql): TTL corto (30s) para reflejar cambios casi en tiempo real.
    • Listas estáticas (list_tokens): TTL medio (60s) para selectores de interfaz.
