Esquema de Base de Datos

El sistema utiliza PostgreSQL 17. El modelo de datos se divide en tablas transaccionales (almacenamiento de logs y entidades) y tablas agregadas (para consultas rápidas de métricas).

1. Bots y Perfiles

Gestión de los activos monitorizados y su clasificación.

bots

Tabla principal de inventario.

  • PK: token (Texto). El token de la API de Telegram.
  • Columnas clave:
    • is_active: Booleano. Controla si el listener debe procesar este bot.
    • bot_id: Entero (BigInt). Identificador único de usuario en Telegram.
    • last_checked_utc: Timestamp de la última verificación de estado.

bot_profiles

Información generada por el módulo de análisis (LLM).

  • Relación: 1:1 con bots.
  • Columnas clave:
    • actor_intent: Clasificación del propósito del bot (ej. 'Stealer', 'Support').
    • risk_level: Nivel de riesgo asignado.
    • detected_ttps: Campo JSONB que contiene una lista de tácticas detectadas.

bot_tags y bot_tag_map

Sistema de etiquetado.

  • Relación N:M entre bots y etiquetas.
  • Las etiquetas se eliminan en cascada si se borra el bot asociado.

2. Mensajería e Ingesta

Almacenamiento de los datos interceptados.

messages

Registro de mensajes recibidos.

  • Restricción: UNIQUE (token, message_id, date_utc). Evita la inserción de mensajes duplicados.
  • Columnas clave:
    • text: Contenido del mensaje.
    • text_sha1: Hash SHA1 del texto para agrupamiento y detección de duplicados.
    • raw_json: Payload original de Telegram en formato JSON.

entities

Datos extraídos del texto de los mensajes (Regex/Parsers).

  • Tipos (etype): email, crypto_wallet, url, domain, ip.
  • Restricción: UNIQUE (message_pk, etype, value).
  • Incluye context_snippet para referencias.

attachments

Metadatos de archivos adjuntos.

  • Almacena ruta local, tamaño, tipo MIME y hash SHA256.

3. Inteligencia y Malware

Tablas relacionadas con la atribución de amenazas y análisis de binarios.

samples_intelligence

Registro de archivos de malware analizados.

  • PK: sha256.
  • Columnas clave:
    • imphash, ssdeep: Hashes para análisis de similitud.
    • origin_url: URL de donde se obtuvo la muestra (si está disponible).

hash_origin

Tabla de enlace (Join Table).

  • Vincula un token de bot con el hash de malware (sample_sha256) que lo contenía. Permite trazar el origen del bot.

malware_similarity_links

Resultados de comparación de similitud (Fuzzy Hashing).

  • Registra pares de hashes (sha256_a, sha256_b) y su puntuación de similitud.

4. Red y Operadores

Estructuras para el análisis de grafos y atribución.

social_identities y social_graph_edges

Grafo de interacciones en Telegram.

  • Nodos: Usuarios o canales.
  • Aristas: Tipos de interacción (ej. FORWARD_FROM).

operator_profiles

Registro de actores identificados.

  • Roles asignados: COMMANDER (envía comandos) o COLLECTOR (recibe datos).
  • Estadísticas de actividad por actor.

infrastructure_intelligence

Datos de red externos.

  • Almacena IPs, Dominios, ASNs y datos de geolocalización vinculados a los bots u operadores.

intel_traffic_flow

Tabla de agregación de tráfico.

  • Almacena volúmenes de mensajes entre entidades.
  • Clasifica el tráfico en INBOUND, OUTBOUND y LATERAL.

5. Métricas Agregadas

Tablas pre-calculadas para optimizar el rendimiento de las consultas del dashboard.

  • metrics_bot_daily: Conteo diario de mensajes y entidades por bot.
  • metrics_language_daily: Conteo por idioma detectado.
  • metrics_word_daily: Frecuencia de palabras.
  • metrics_text_templates: Agrupación de mensajes idénticos (por hash) para detección de spam/campañas.

6. Sistema

monitored_assets

Lista de activos bajo vigilancia (Watchlist).

  • Elementos (emails, dominios) que generan alerta si aparecen en los mensajes interceptados.

system_health

Métricas operativas.

  • Espacio en disco y uso de recursos del servidor.
