Listener Service

El Listener es el componente de interceptación en tiempo real. Utiliza la librería Telethon (MTProto) sobre asyncio para gestionar conexiones concurrentes a la API de Telegram. Su diseño prioriza la estabilidad de la conexión y la separación de responsabilidades entre la recepción de datos y su procesamiento.

Arquitectura de Flujo de Datos

El sistema implementa un patrón Producer-Consumer utilizando colas en memoria (asyncio.Queue) para evitar que la latencia de base de datos o red bloquee el bucle de eventos principal.

Componentes Principales

1. Orquestación (main.py)

Punto de entrada que gestiona el ciclo de vida de los workers y clientes:

  • OpSec Check: Valida la anonimidad de la conexión antes de iniciar (Kill Switch).
  • Gestión de Colas: Inicializa INGEST_QUEUE y SEND_QUEUE.
  • Forwarder Maestro: Instancia el cliente especial encargado de rebotar los mensajes al canal de los analistas.

2. Gestión de Sesiones (client_manager.py)

Administra el enjambre de clientes de bots:

  • Persistencia: Utiliza archivos .session (StringSession) almacenados en disco para mantener la autenticación entre reinicios.
  • Refresher Loop: Tarea en segundo plano que consulta la tabla bots cada 10 minutos. Si detecta nuevos tokens añadidos, levanta nuevas instancias de cliente sin detener el servicio ("Hot-loading").
  • Depuración Automática: Captura errores AccessTokenExpiredError y marca automáticamente los bots revocados como inactivos en la base de datos.

3. Lógica de Interceptación (handlers.py)

Procesa cada evento NewMessage entrante:

  • Clasificación de Contexto: Distingue entre mensajes de chat privado (potencial comunicación con el operador) y mensajes de canales/grupos (infraestructura de difusión).
  • Grafo Social: Inspecciona cabeceras fwd_from para extraer identidades de usuarios o canales ocultos.
  • Descarga Segura: Gestiona la descarga de adjuntos a la carpeta local media/, asociando el path al registro del mensaje.

4. Motor de Ingesta (ingest/worker.py)

Worker dedicado a la escritura en base de datos:

  • Firma Estructural: Genera un hash SHA1 basado en la estructura del mensaje (eliminando datos variables) para agrupar alertas repetitivas en el dashboard.
  • Transaccionalidad: Inserta el mensaje, entidades y metadatos de adjuntos en una única transacción atómica para garantizar consistencia.

Mecanismos de Robustez

Rate Limiting (ForwarderSender)

Para evitar que Telegram bloquee la cuenta de análisis por FloodWait, el sistema utiliza un Bridge Worker y una clase ForwarderSender que implementa un ritmo de envío controlado (ej. 1.5 mensajes/segundo).

Watchdog Externo (watchdog.py)

Script independiente ejecutado por el sistema operativo (Cron/Systemd). Monitoriza la tabla messages; si no detecta actividad de ingesta en los últimos 30 minutos, asume un fallo silencioso de conexión y fuerza el reinicio del contenedor.
